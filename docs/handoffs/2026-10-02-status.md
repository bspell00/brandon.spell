## Hosting and the contact form

- **Cloudflare Pages project `brandonspell`** builds every push. `master` is production; other branches get preview URLs (`<branch>.brandonspell.pages.dev`).
  - Build command (set in the dashboard): `npm ci --omit=dev`. It installs `worker-mailer` for the form; without it the build fails "Could not resolve worker-mailer".
  - The Cloudflare GitHub app only had `ark-church` selected at first; `brandon.spell` was added on 2026-10-01. If builds stop triggering, check github.com/settings/installations.
- **Domain:** `www.brandonspell.com` is a Pages custom domain (CNAME to `brandonspell.pages.dev`). The bare `brandonspell.com` still points at GitHub Pages, which redirects to `www` because of the `CNAME` file. Don't delete `CNAME` until that redirect moves to Cloudflare.
- **Form:** `contact.html` posts to `functions/api/contact.js`, which sends through Gmail SMTP and redirects to `/contact?sent=1` or `?error=…`. Secrets `GMAIL_USER` and `GMAIL_APP_PASSWORD` are set in the Cloudflare dashboard for Production and Preview. Tested end to end on 2026-10-01 (real email received on both preview and production).
- **Local dev:** `npm run dev` (wrangler on port 8000). The form needs a gitignored `.dev.vars` with the two secrets to send locally.
- **Cache busting:** pages link `css/custom.css?v=4` and `js/main.js?v=3`. Cloudflare tells browsers to cache CSS for 4 hours, so bump the number when styles or the script change.
